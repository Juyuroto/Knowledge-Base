# [PROXMOX] Erreur 400 allow-ksm lors du changement de RAM

> **En résumé :** Impossible de modifier la quantité de mémoire RAM d'une VM Windows depuis l'interface Web de Proxmox en raison d'une option dépréciée (**allow-ksm**) rejetée par l'API.

---

## Informations

- **Catégorie :** Proxmox
- **Date :** 2026-08-06
- **Système / Version :** Proxmox 8.4.0

---

## Erreur & Symptômes

Lors de la modification de la mémoire RAM via l'interface graphique (GUI) de Proxmox, la modification échoue avec un code HTTP 400.

```
Parameter verification failed.
 (400)

allow-ksm: property is not defined in schema and the schema does not allow additional properties
```

---

## Cause du problème

L'option **allow-ksm** (Sharing / KSM) a été supprimée ou dépréciée dans les versions récentes du schéma d'API de Proxmox. Cependant, l'interface graphique Web continue d'env"oyer ce paramètre obsolète en arrière-plan lorsque la gestion dynamique de mémoire (Ballooning) est active, déclenchant un rejet strict de la requête par le serveur Proxmox.

---

## Solution

Pour contourner le bug de la GUI et appliquer la nouvelle allocation de RAM (ex: 24 Go = 24576 MiB ou 28 Go = 28672 MiB), il faut désactiver le Ballooning et forcer la mémoire via le terminal Proxmox.

1. Ouvrir le Shell du nœud Proxmox.

2. Exécuter la commande suivante (en remplaçant 101 par le VMID concerné) :

**101** qui est l'ID de la VM

```bash
qm set 101 --memory 24576 --balloon 0

qm set 101 --memory 28672
```

3. Actualiser la page de l'interface Proxmox (F5). La mémoire est correctement mise à jour sans erreur.
